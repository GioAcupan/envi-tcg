# UPDATE-1 rules revision and evolution toggle

**Spec:** [architecture/update-1-spec.md](../architecture/update-1-spec.md). Types: §3. Rules contract: Appendix A. Cards: Appendix B. Inferences: §9. Acceptance trace: §7.

**Agent routing:** GPT 6.1 Sol via Orca at medium effort for T1 and T2; Haiku subagent for T3; Gemini 4 Argon via Orca at high effort for T4. No Sonnet.

**Why no separate stub wave:** the engine already exists and every interface change lands in one module set (engine, data, ruleset) owned by one lane, so a stub-and-freeze wave would only serialize the same lane. T1 writes the §3 types verbatim and the acceptance tests at the §7 seams; wave 1 lanes build against T1's merged result.

## Wave 0

### T1 — Engine, default data and ruleset for UPDATE-1

**Design line:** make the engine play UPDATE-1 exactly as spec Appendix A says, with the Appendix B cards, through the unchanged `newGame` / `checkAction` / `applyAction` seam.

- `src/engine/types.ts` = spec §3 verbatim. Optional fields may be added if needed; report them.
- `src/ui/` and `src/App.tsx`: **compile-only** fixes so `npm run typecheck` and `npm run build` stay green against the new types (delete references to removed fields/actions, the simplest stand-in for new ones). No UI features, layout or styling; T2 and T3 own the real UI work in wave 1.
- Rewrite `src/engine/index.ts` and `src/engine/abilities.ts` for Appendix A. Remove processing, the shared center, Fallen Leaves, Day/Night, the Flood choice and the `decompose`/`choose` actions. Log prefix becomes `Round N: `. Keep `checkAction` and `applyAction` on one validation path. Random choices (Flood, reshuffle) use the seeded RNG in state.
- `src/data/cards.ts` = Appendix B (36 per deck; the `art` field points at `art/<id>.svg` for the six new ids and reuses existing art for surviving ids); `src/data/params.ts` = §3 defaults; `src/data/interpretations.ts` = one entry per §9 assumption, ids `R1`–`R5` (`major: true`) and `I1`–`I14`, text in plain English a student can check against the PDF.
- `src/ruleset/index.ts`: `version: 2`, §4 failure behavior, storage key bumped to `envi-tcg.ruleset.v2` (old key ignored).
- Tests are rewritten for UPDATE-1 (they currently assert the first draft): `tests/acceptance/*.test.ts` hold one `describe` per §7 row U1–U10 and U13, arranged only through `newGame` + referee ops + actions; `tests/acceptance/helpers.ts` keeps its helpers (events at 0 copies unless overridden). Own extra cases go in `tests/engine.lane.test.ts` and `tests/ruleset.lane.test.ts`.
- Acceptance (given/when/then, each a test):
  - given defaults, when `newGame`, then each player has 36 cards across deck+hand and 5 in hand; with `evolutionEnabled: false`, 26 and no `adaptation` card anywhere, and playing an adaptation obtained by referee is illegal ("Evolution is off").
  - given Emergent Plant in hand, when played, then pool −2 C −0.5 N, AP −1, `stored` = 6/1/0/0; after both players end turn, stored C = 7 and pool +2 O2 +1 C; with Drought this round an Aquatic Plant produces nothing and other producers yield 1 O2.
  - given a dead plant worked by Freshwater Shrimp, when a round ends, then the shrimp's owner gains 3 C from the plant's stored C and the shrimp's lifespan does not drop; with Tubifex Worm also on it the Tubifex releases 1 C + 1 extra C + 1 N; when the plant's C reaches 0 it goes to its owner's discard with nothing left on the field, and its workers are free to assign again.
  - given a Shrimp working a dead plant and a Carbon Bacteria played on it, when a round ends, then 6 C reach the owner while the plant loses only 3 C, and the bacteria is back in its owner's hand; Nitrifying moves all the card's N; Phosphorus gives +1 P; a microbe on a card with no worker stays put.
  - given a Small Fish and an opponent's living detritivore, when eat, then the prey's stored adds to the fish, the prey sits under it, AP −1; a second eat that round is illegal; Protected prey is illegal.
  - Strong Rainfall: each player +1 P; a player at 3 P with living algae has each algae's stored doubled unless they have a living Freshwater Snail. Heat Wave: an organism whose owner can't pay upkeep+1 dies (producers included). Flood: each player loses one random living organism and gains 1 C, or gains 1 P with none.
  - given pool 50/15/1 via referee, then that player wins.
  - an empty deck draws from the reshuffled discard pile.
  - `importRuleset` of a version 1 file → `ok: false` with §4's message; `loadRuleset` with a stored version 1 returns defaults.
- Edge cases: an illegal action changes only `lastError`; fractional pools display and compare correctly (no rounding in the engine).

## Wave 1

### T2 — Game screen for UPDATE-1 and the evolution switch

**Design line:** the tablet game screen shows and plays UPDATE-1's state, with nothing left of Day/Night, the shared center or the Flood choice.

- Interfaces: consumes T1's engine and spec §3 types; `GameScreen` props become `{ ruleset: Ruleset; onRulesetChange(r: Ruleset): void }` so the game menu can flip `params.evolutionEnabled` (App passes the same handler the editor uses; the switch says the change applies to the next new game and offers "New game now").
- Board per spec §5: worked cards stay visible under their detritivores and microbes (PDF C.4 stacking); dead cards sideways (C.2); `stored` shown as Biomass; producers show growth and yield; an "Evolution off" chip when disabled. Targeting: microbes tap a dead card; detritivores tap a card they can work (`assign`); consumers tap prey. Closeup facts follow the new fields. Referee panel drops Set Day/Night and the center zone.
- Keep the DESIGN.md look and the no-scroll rule (envi-tcg-9bf9).
- Acceptance: given a new game at 1024×768 and 768×1024, when two players play a producer, a detritivore assigned to a dead card, a microbe on it, a consumer eating, and end turns, then each step is reachable by tapping, the page never scrolls, and there are no console errors (Playwright smoke; screenshots for the operator, `hitl`). Toggling evolution off then New game yields hands with no adaptation cards and the chip shows.
- Own test file `tests/ui.lane.test.ts` for any pure helpers (e.g. `src/ui/game/actions.ts` targeting).

### T3 — Editor and Interpretations screens for UPDATE-1

**Design line:** let the group edit every new card field and param, including fractions, and switch evolution off.

- Card table columns follow §3 `CardDef`: cost C/N/O2, biomass C/N/P, growth and yield (C/N/P/O2), upkeep, release (C/N/P), lifespan, tags, canEat, eatsAlive, copies, text. Remove o2Produced, trophicLevel, fallen leaves, processRounds and decomposeApCost. Number inputs accept decimals (`step="any"`).
- Params form gains an "Evolution / adaptation mechanics" checkbox (off = baseline), and the deck-size hint says 36 with evolution on and 26 with it off.
- Interpretations screen unchanged except it lists the new entries (major first).
- Acceptance: editing a decimal cost to 0.5 calls `onChange` with exactly that change; unchecking evolution sets `params.evolutionEnabled` false; Export then Import yields an equal ruleset; importing a version 1 file shows §4's error and keeps the current ruleset (orchestrator smoke).
